## Forum audit — October 26, 2026

The items below are pending. Reviewed the iOS feed, search, discussion, community directory, and composer in the iPhone 17 simulator with demo data. Posting, replies, voting, membership, watching, and reporting were traced in source without submitting changes. Authenticated backend behavior, physical-device VoiceOver, and large threads remain unverified. Forum UI findings refer to [ForumViews.swift](../LiftRankApp/Features/Community/ForumViews.swift); service findings refer to [SupabaseServices+Social.swift](../LiftRankApp/Services/SupabaseServices+Social.swift).

### High priority: completeness and content protection

- [ ] **Apply feed scope, search, and sorting before pagination.** Top, Most discussed, search, and followed-community filtering operate only on downloaded posts. If none of the first 50 posts belongs to a followed community, the empty state also hides Load more. Query the intended dataset through the service and retain pagination. Verify matches and high-scoring discussions beyond the first page, including Following with no first-page matches.
- [ ] **Protect discussion, edit, and reply drafts.** Drafts live only in view state, and the composer can dismiss without a discard check. Inputs remain editable during submission; a successful reply clears text entered after the request began. Preserve drafts across ordinary navigation or confirm discard, and prevent requests from erasing subsequent edits. Verify Back, swipe dismissal, Cancel, delayed success, and failure/retry.
- [ ] **Replace silent content truncation with visible validation.** The service cuts titles to 180 characters, post bodies to 10,000, and comments to 5,000 without corresponding composer limits or warnings. Show limits and actionable validation for creation and editing. Verify boundary values and ensure saved content matches the accepted draft.
- [ ] **Make failures recoverable without hiding useful content.** Load-more and membership failures set the same page-level error that replaces the feed; successful loads do not clear that error. Thread failures can leave the loading indicator visible alongside an error. Separate initial-load and action failures, retain loaded content, and offer Retry/refresh. Distinguish unavailable discussions from network failures when opening notification links. Verify failure → retry → success for each path.

### Medium priority: workflow and state

- [ ] **Provide accurate, actionable empty states.** A no-match search currently renders a blank feed because the empty check runs before search filtering. Distinguish no search matches, no discussions in this community, and no joined communities; offer Clear search, Clear filters, or Browse communities as appropriate. Verify each combination without resetting unrelated choices.
- [ ] **Prevent outdated requests from replacing the selected feed.** Community loads and pagination have no request identity or cancellation guard. Ensure only responses for the current selection update posts, offsets, and loading state. Verify rapid community switches and switching while Load more is pending.
- [ ] **Update vote counts and prevent overlapping vote requests.** Post voting changes the selected arrow but leaves the displayed post count unchanged. Reconcile the count with the accepted vote and serialize repeated taps for both posts and comments. Verify upvote, removal, switching direction, delayed responses, and failed requests.
- [ ] **Restore discussion notification preferences.** The watch state starts false each time and is not loaded with the discussion. Read the saved preference and show a clear Follow discussion/Unfollow discussion action with a pending state. Verify reopening a watched thread and changing the preference once.
- [ ] **Make the publishing destination deliberate and the result visible.** From All, the composer silently selects the first community. Require a destination choice when no community context exists, explain relevant posting restrictions, and retain an explicitly selected community. After publishing, open or link to the created discussion instead of only refreshing a feed that may filter it out. Verify publishing from All, Following, and a filtered community.
- [ ] **Unify community membership states and feedback.** The directory shows Pending/Muted while the feed header reduces state to Join/Joined; Joined immediately performs Leave. Use explicit actions, consistent pending status, per-community progress, and local error feedback. Do not treat failed membership reads as confirmed non-membership. Verify pending approval, joined, muted, leave, repeated taps, and request failure.
- [ ] **Make replying preserve conversation context.** Reply selects a parent but does not focus or reveal the composer. Focus the input, show the target author, and provide a clear route to the submitted reply. A notification comment should be scrolled to and highlighted once rather than repeatedly pulling the reader back when comment count changes. Verify nested replies, keyboard behavior, and notification entry.
- [ ] **Separate report confirmation from errors.** A successful report is assigned to the error string and rendered in the error treatment below the discussion. Show a visible success confirmation, retain a distinct retryable failure state, and allow useful context if supported by the report flow. Verify post and comment report outcomes without duplicate submissions.
- [ ] **Share a navigable discussion link.** Sharing currently sends only the title and body. Include a supported discussion URL that opens the original thread, with sensible unavailable/access-denied handling. Verify app-installed and browser entry, plus a removed or restricted discussion.
- [ ] **Resolve authors consistently and support profile navigation.** Author names depend on the existing profile cache and otherwise fall back to generic member labels; avatars are generic and author labels do not open profiles. Load permitted public author information through the service and provide a profile destination. Verify an uncached author and a deleted or unavailable profile.

### Visual clarity and usability

- [ ] **Improve community discovery and explain feed scope.** The directory is a stack of large cards with no search, while feed search only finds community names through downloaded posts. Add directory search, compact repeated card content, and make visibility/join requirements understandable. Keep Following's community scope clear and explain that For You currently consists of joined communities plus pinned posts. Verify a community with no posts and a longer directory.
- [ ] **Make thread structure easier to scan.** Preserve community context in a discussion, distinguish nested replies at narrow widths, and expose collapsed-reply counts with a visible expand action. Verify long replies, deep nesting, and accessibility text sizes without crowding the reading area.
- [ ] **Expose selection and action meaning to accessibility.** Feed selection is primarily conveyed through color, post upvote is announced as its count, and the watch bell lacks a state-specific action label. Add selected traits and descriptive labels/values for feed, vote, and notification controls. Verify VoiceOver order, action names, state changes, and touch targets on a device.
- [ ] **Make demo behavior internally consistent.** Debug builds append sample posts regardless of account mode, feed cards hide the demo tag, and sample cards show zero replies while their threads contain comments. The thread says read-only but the reply submission path can append a local demo comment. Restrict samples to the intended demo context, label them in the feed, align counts, and choose one consistent interaction model. Verify demo and authenticated debug sessions separately.

Implementation constraint: any database correction must be forward-only unless deployment history proves the migration is unapplied everywhere. Remote migrations require explicit instruction and environment confirmation; RLS, grants, triggers, and security-definer changes require runtime SQL security tests.
